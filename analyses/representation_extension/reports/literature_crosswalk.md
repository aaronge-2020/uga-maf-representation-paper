Reading note. Three naming traps run through this crosswalk. First, relevance frequency in Ozcan Simsek 2019 is supervised and class specific. Second, the 96 features that Lee et al. 2019 call mutation signatures are counted trinucleotide channels, not fitted signature exposures. Third, MuAt in Sanjaya et al. 2023 is not a fixed count vector at all. MuAt learns embeddings for individual mutations and then uses attention. Sections B, C, and D take each trap in turn.

## B. Ozcan Simsek 2019: class relevance weighting, and whether it can be used on an unlabeled patient

### B.1 What the paper says, in its own words

The tf-rf section defines the method as class dependent from the start. Methods, Tf-rf based mutation model:

> "tf-rf (term frequency-relevance frequency) based data representation is adapted. Similarly to tf-idf, tf-rf is also used in information retrieval and text mining. Unlike tf-idf, tf-rf is a supervised statistical measure proposed in [32]. It is used to evaluate how important a word is to a class of documents in a collection. In tf-rf, a word may have different weight values for different classes."

The next paragraph ties the value for one sample to that sample class label. Same section:

> "In our context, the tf-rf value measures how important a gene mutation is to a sample by using the information of its class label. If the particular gene mutation is encountered more in one class compared to the other classes, the corresponding rf and tf-rf values are higher than for the other classes."

The formula then needs a named class c. Eq. 3 and Eq. 4, same section:

> tf-rf(g,s) = tf(g,s) x rf(g,c)
>
> rf(g,c) = log(2 + a / max(1,b))

where, in the text after Eq. 4, a is "the number of samples in class c which contain mutation in gene g" and b is "the number of samples in other classes which contain mutation in gene g."

BM25-tf-rf keeps the same dependence. Eq. 8, Methods, BM25-tf-rf based mutation model: BM25-tf-rf(g,s) = BM25-tf(g,s) x rf(g,c), with "The rf definition is the same as in tf-rf."

The Discussion gives a worked example that only makes sense if the class is already known. Discussion: sample 79 is a breast cancer patient and sample 164 is a brain cancer patient. For gene HAPLN3, "The BM25-tf-rf value for HAPLN3 in Sample-79 is 1.016021 whereas it is 0.794813 in Sample-164." For gene BRF1, the values are 1.323967 in sample 79 and 1.085498 in sample 164. The paper then states the point directly:

> "When we consider the Feed Forward NN classification model, the weights for these gene features is the same for both samples. Therefore, the distinction of predicted cancer type results arise from the difference in BM25-tf-rf weights."

The Conclusion repeats the design intent. Conclusion: "The supervised weighting approach of tf-rf successfully reflects this class-mutation relationship."

### B.2 Two different steps must not be merged

Step 1, fitting the rf table, is legitimate supervised learning. From labelled training samples, count a and b for every gene and every class, and store one rf value per gene per class. That uses training labels only. It is no different in kind from fitting any other supervised statistic on training data.

Step 2, applying the table to one new patient, is where the method breaks. To build the single feature vector that the classifier expects for patient s, Eq. 3 needs one rf column, the column for class c. For a training patient, c is the known label, so the vector is well defined. For a new patient whose cancer type is the thing to be predicted, c is unknown. The transformation of that patient, as written, depends on that patient true class.

Put concretely for the 10 class task in Table 1: one unlabeled patient with a fixed set of gene counts has 10 different tf-rf vectors, one per candidate class, and 10 different BM25-tf-rf vectors. The paper defines all 10. It does not define which one is the patient representation.

### B.3 Verdict: a faithful, inference safe implementation is not possible from the paper as published

No faithful inference safe implementation exists, for this exact reason: the paper gives no rule that selects, combines, or removes the class argument c at prediction time.

Each obvious repair adds a rule that is not in the paper, so each repair is a new method, not a reproduction:

1. Use the patient true class to pick c. This is label leakage. The label is not available for a new patient, and in a test set it would use the answer to build the input that predicts the answer. Performance measured this way does not estimate performance on unlabeled patients.
2. Predict a class first with another model, then use that predicted class to pick c, then classify again. The paper describes no two stage procedure, no first stage model for this purpose, and no handling of first stage errors. The result would depend on the added first stage.
3. Build all 10 class specific vectors and feed all of them in, or average the rf values across classes, or take the maximum rf across classes. None of these aggregations appears in Methods, Data representation models, Eq. 1 to Eq. 8. Averaging also removes the class contrast that rf was built to create, because a gene that is common in one class and rare elsewhere would no longer receive the high value for that class and the low values for the others in separate inputs. It would receive one blended value for every patient.
4. Train 10 separate classifiers, one per assumed class, and combine their outputs by a stated rule. No such set of classifiers or combination rule is described.

Because the missing rule decides the input itself, this is not a small implementation detail that can be filled in silently. Two careful teams following the paper would build different test inputs and could report different accuracies, and neither could claim the paper specified its choice.

Audit consequence for the benchmark: do not implement tf-rf or BM25-tf-rf by looking up the outer test patient true class. Do not label any class averaged, predicted class, or multi vector variant as a faithful reproduction of Ozcan Simsek 2019. If such a variant is ever run, label it as a new adaptation, state its selection rule in full, and keep it out of the primary published method comparison. The headline 76.44 percent in Table 6 belongs to a representation whose test time definition is incomplete in this sense, which is one more reason not to carry that number into a direct comparison. See Section E.

One point in the paper favour should be recorded fairly. The paper does state a clean evaluation intent for classifiers and tuning: an 80 percent training and 20 percent test split, tuning by cross validation on the training set, and test instances excluded from tuning and training. Methods, Evaluation strategy. That statement does not resolve the class argument problem above. A split can be clean for model fitting while the feature definition for a test patient still needs that patient label.

### B.4 The inference safe alternative: TF-IDF fitted on training data only

Use the tf-idf model from the same paper, Eq. 1 and Eq. 2, with one change of scope that the benchmark protocol requires and that does not change the formula: fit every corpus statistic on the training partition only, inside each inner and outer fold, and freeze it for validation and test patients.

Recommended exact variant, to be recorded in the benchmark protocol as R5:

For gene g and patient s:

- tf(g,s) = count of eligible mutations of gene g in patient s. Eligible means the benchmark own eligibility rule for that run (for the panel restricted gene count runs, the same eligible coding mutations that feed the gene count representation). The patient count uses only that patient data.
- df_train(g) = number of training patients who have at least one eligible mutation in gene g.
- N_train = number of training patients.
- idf_train(g) = log(N_train / df_train(g)), following Eq. 2 of Ozcan Simsek 2019.
- tf-idf(g,s) = tf(g,s) x idf_train(g), following Eq. 1 of Ozcan Simsek 2019.

Decisions that must be written down, because the paper leaves them open:

- Log base. The paper writes log without a base in Eq. 2 and Eq. 4, so the base is UNVERIFIED in the original. This draft recommends natural log, and recommends recording that choice in the protocol and in code. Changing the base multiplies every idf value by one constant, but a regularized classifier is not fully scale free, so the base is a real, if small, modelling choice.
- Vocabulary. Keep only genes with df_train(g) of at least 1. A gene never mutated in training has no idf and is dropped, not given a made up weight. A gene with df_train(g) equal to N_train gets idf equal to log(1), which is 0, and so contributes 0 for every patient. That follows Eq. 2 directly and needs no smoothing constant.
- No smoothing in the primary variant. Adding 1 to numerator and denominator, as some text mining toolkits do by default, would be a deviation from Eq. 2. If a smoothed version is wanted, run it as a named sensitivity analysis, not as the primary R5.
- No BM25 dampening in the primary variant. A BM25-tf-idf version exists in the same paper, Eq. 5 to Eq. 7, with k tuned to 0.8 in Table 2. It is also inference safe, because BM25-tf uses only the patient own count and the constant k. It can be a named sensitivity analysis. The primary variant stays plain tf-idf so that the contrast with raw gene counts isolates one change at a time: corpus weighting on, count dampening off.

Why this variant is the right substitute:

1. It comes from the same paper and the same Methods section as tf-rf, so the benchmark still tests the published statistical weighting idea, in the one form from that paper that is fully defined for a new patient.
2. It needs no label for the patient being transformed. idf_train(g) is a single number per gene, not one number per gene per class. Two patients with the same gene counts get the same vector regardless of their true or future predicted classes.
3. It separates two questions that tf-rf merges. Whether corpus frequency weighting helps is testable with tf-idf. Whether class contrast weighting helps cannot be tested faithfully at test time, for the reasons in Section B.3, and should not be smuggled in through leakage.
4. Fitting on training data only matches the benchmark rule for all learned transforms: weighting, scaling, feature selection, and vocabulary filtering belong inside the training partition, at inner validation level as well as outer test level. Computing idf once on the full cohort would let test patients influence their own and each other inputs through df, even though idf uses no labels.

Label for reporting: call this representation "TF-IDF, Ozcan Simsek 2019 Eq. 1 and Eq. 2, fitted on training data only." Do not call the benchmark run a reproduction of the BM25-tf-rf result in Table 6.

## C. CPEM: the gene count feature idea is not the full CPEM model

### C.1 The mutation count idea, on its own

The part of Lee et al. 2019 that matches a gene count representation is one feature block:

- 22,421 gene level values.
- For each gene and each sample, the value is the count of protein altering SNVs and indels in that gene in that sample.

Anchor: Methods, Feature Construction, quoted in Section A. Fig. 1 calls this block "gene-level mutation profiles."

That block alone, in the paper own stepwise test, gave 46.9 percent accuracy. Results, Efficacy of Various Mutation Features, and Fig. 3a: a random forest starting "from the gene-level mutation profiles only" reached 46.9 percent, before any other block was added. That stepwise test used a random forest as an initial prediction model and 10 fold cross validation, not the final CPEM ensemble. Same section. So 46.9 percent is the paper own number for the count block in that test setting, and 84.09 percent is not a number for the count block.

A benchmark run that implements only per gene protein altering counts is an implementation of this feature idea. It is a representation adaptation inspired by CPEM. It is not a reproduction of CPEM.

### C.2 The full CPEM model

Full CPEM adds four more feature groups, then selects features, then ensembles two classifiers. Fig. 1 lists the full vector, and Methods, Feature Construction, gives the same list:

1. 22,421 gene level mutation profile counts, as above.
2. 2 mutation rates.
3. 6 mutation spectra.
4. 96 trinucleotide context channels, called mutation signatures in the paper. See Section C.3.
5. 13,040 gene level log2 copy ratio values from somatic copy number alterations.

Total: 35,565 features. Fig. 1 and Methods, Feature Construction.

The stepwise random forest accuracies in Fig. 3a show what each addition did in that test: 46.9 percent for mutation profiles alone, 51.2 percent after adding mutation rates, 58.5 percent after adding mutation spectra, 61.0 percent after adding SCNAs, and 72.7 percent after adding the 96 channels. Results, Efficacy of Various Mutation Features. Two lessons follow. First, copy number alone added a step in that sequence, so a mutation only model is missing a real input of the published model. Second, even all five blocks with a random forest reached 72.7 percent in that stepwise test, well below the 84.09 percent headline. The rest of the headline comes from feature selection and the ensemble.

Feature selection: LSVC selection was chosen over extra trees and LASSO. Results, Optimal Feature Selection, and Fig. 3b. Peak accuracy came at about 4,000 to 8,000 selected features. Results, same section, and Fig. 3c.

Classifiers and ensemble: a deep neural network with three hidden layers of 2,048 units, Adam, learning rate 1e-5, and 40 percent dropout. Results, Experimental setup. Plus a random forest, trained on the same selected features. Fig. 1. The ensemble averages the two models output probabilities per cancer type. Methods, Cancer Type Classification.

Headline in that full setting: 84.09 percent average accuracy for 31 types. Results, Putting it all Together, and Fig. 4.

Reporting rule for the benchmark: write "gene counts in the style of the CPEM mutation profile block" for a counts only run. Write "CPEM" only for a run that also uses SCNA log2 ratios, rates, spectra, the 96 channels, LSVC selection fitted inside training data, and the DNN plus random forest probability averaged ensemble, on a comparable cohort. The benchmark gene count runs described in the audit brief do not meet that bar, and should not be presented as CPEM reproductions.

### C.3 What the 96 channels actually are, and what they are not

What they are: counted SNV context types. Methods, Feature Construction defines them by a product: "{A, C, G, T} x 6 mutation spectra x {A, C, G, T}." That is, one channel for each choice of base before the mutated base, each of the 6 pyrimidine reference substitution types, and each choice of base after it. 4 x 6 x 4 = 96. A channel name therefore looks like a trinucleotide pattern. Discussion names a top feature as "CCT.C > T," and Results, Efficacy of Various Mutation Features, lists it among the top ten features as "one mutation signature (CCT.C > T)." Read in light of the Methods definition, that label names one of the 96 counted context channels.

What they are not: fitted mutational signature exposures. A fitted exposure is a weight for a known signature profile, estimated for one patient by fitting that patient counted spectrum as a mixture of catalogue signature profiles. Lee et al. 2019 describe no such fitting for these 96 values: no catalogue signature matrix, no fitting algorithm, no non negativity or sum constraint, and no exposure variable appears in Methods, Feature Construction. The 96 values are built directly from the patient SNV calls by counting contexts.

The paper own Discussion shows the difference. To interpret the CCT.C > T channel, the authors had to look outside their features, to COSMIC: Discussion states that they "referred to the COSMIC data to identify signatures with a high frequency of CCT.C > T mutations, and confirmed that the frequency of CCT.C > T mutations was the highest in Signature 23 and 19." A channel that is frequent inside two different catalogue signatures cannot itself be an exposure to either signature. One counted channel contributes to many signatures, and one signature spreads its counts across many channels.

Practical consequences:

- Do not rename the benchmark SBS96 count representation as signature exposures. SBS96 counts and the CPEM 96 channels are the same kind of object: counts by trinucleotide substitution type. Fitted SBS signature activities are a different representation and must stay separate, as the audit brief also requires for spectra versus fitted signature activities.
- Do not cite Lee et al. 2019 as evidence that fitted signature exposures improve cancer typing by the step shown in Fig. 3a. The step from 61.0 percent to 72.7 percent in that figure is the step from adding counted context channels, labelled Sig. in Fig. 3a, in a random forest stepwise test.
- If the benchmark wants a CPEM style channel block, the faithful block is raw or normalized trinucleotide counts. The paper does not state the normalization for spectra and channels in the text read, so that choice is UNVERIFIED in the original and must be recorded as a benchmark decision, for example counts, or counts divided by total SNV count, with the total kept as a separate burden feature if the protocol says so.

A related caution on the top feature list: the top ten features in Results, Efficacy of Various Mutation Features, mix kinds on purpose. They are two mutation rates, one context channel, two spectra, and five single mutated genes: VHL, IDH1, BRAF, APC, and KRAS. No single feature kind explains CPEM performance.

## D. MuAt: input representation, fixed recipe versus searched architecture, cohorts and metrics

### D.1 Input representation: tokens and embeddings, not counts

MuAt takes a catalogue of individual somatic mutations for one tumour. Abstract and Background: MuAt "utilizes the attention mechanism on individual mutations instead of aggregated mutation counts," and integrates mutation type and genomic position "at a per-mutation level, instead of representing type and positions as aggregated counts."

Each mutation becomes three tokens, one per modality. Methods, Model, and Methods, Data preprocessing:

1. Mutation motif token. The mutation written in a three nucleotide sequence context, for example A[C>T]G. Combinations of up to three simple mutations can be represented, which covers MNVs and indels longer than 1 bp. Dictionary size: 3,692 tokens, made of 96 SNVs, 2,170 MNVs, 1,160 indels, 233 SVs, and 33 MEIs.
2. Position token. The genomic position in a 1 Mbp bin, written for example as chr1_11 for chr1:11,000,000 to 11,999,999. Dictionary size: 2,915 tokens.
3. Annotation token. One of 16 combinations of genic (yes or no) x exonic (yes or no) x strand category (4 categories). The strand categories are: pyrimidine reference base on the same strand as a gene, on the opposite strand, mutation overlaps two genes on opposite strands, or mutation is intergenic.

Mutation symbols used inside motifs are listed in Methods, Data preprocessing: six substitutions stated for the pyrimidine base, deletions and insertions of A, C, G, and T, breakpoints for four SV types (deletions, duplications, inversions, translocations), and retrotransposon insertions (L1, Alu, and SVA).

Each modality is one hot encoded separately with its own dictionary, then embedded with a learned embedding, and the three embeddings are concatenated to form the mutation vector. Methods, Model, and Fig. 1. Those vectors enter the attention module, Eq. 1 in Section A. The paper stresses order does not matter: "no order is imposed on the mutations: MuAt treats somatic mutations analogously to a bag-of-words." Methods, Model. Fully connected layers then produce tumour level features and class probabilities. Same section.

Two experimental details belong in any reproduction attempt:

- Negative examples. In some experiments, non mutation events were added as negative examples, built by taking a mutated position from one tumour, encoding the reference sequence there with no mutation symbol, and placing it into another tumour catalogue, in a count equal to the median number of variants per type in the dataset. Methods, Data preprocessing. Whether a given reported model used negatives must be checked per experiment. The text places this under experiments ("In experiments, we also considered..."), not as a universal step for every model. Treat its use in the headline models as UNVERIFIED unless the supplement for that model says so.
- Capacity. At most 5,000 mutations per tumour, set by GPU memory. Methods, MuAt hyperparameter search, model training and validation. Tumours with more mutations are downsampled by random sampling of the catalogue, as described for high burden tumours in Results. Any reproduction must record the sampling rule and seed, because two runs on the same high burden tumour can see different mutation subsets. The paper tested repeat prediction consistency 100 times per tumour for this reason. Results, Evaluation of histological tumour typing performance, and Fig. 3b.

### D.2 Fixed recipe versus architecture search, as published

As published, MuAt is a searched family plus fold ensembles, not one fixed recipe. Methods, MuAt hyperparameter search, model training and validation:

- Searched: embedding dimension in {128, 256, 512}, number of encoder layers in {1, 2, 4}, number of attention heads in {1, 2}, number of fully connected layers in {1, 2}, and which mutation types to include. Mutation type combinations: 15 for PCAWG and 9 for TCGA, shown in Additional file 2, Fig. S2, as cited in that section.
- Fixed during search: learning rate 6e-4, momentum 0.9, minibatch size one, 150 epochs, stochastic gradient descent minimizing cross entropy (Eq. 2), and the 5,000 mutation cap.
- Selection: ten fold cross validation with folds built by splitting each cancer type equally into ten and combining matching folds. In each fold, a model was trained for each hyperparameter combination, and the model with the best validation accuracy in that fold was selected. Hyperparameters and performance per fold are in Additional file 1, Table S2, as cited in that section.
- Reported prediction models: ensembles made from the best model of each fold, ten models in all, with the ensemble score formed by summing the component models class logits and predicting the class with the highest summed score. Same section.

So a single fixed configuration reimplementation is, at best, one point in the published search space. It should be labelled a fixed recipe sensitivity analysis, not "MuAt" without qualification. That matches the audit brief instruction to treat a verified architecture searched implementation as the primary neural comparator and a fixed recipe as a sensitivity, once the local implementations have been verified for patients, seeds, inputs, and checkpoints.

One fixed configuration is named in the paper, and it should not be confused with the headline cross validated ensemble. Methods, same section: "The model selected for analysis of tumour typing performance in sparse data was trained on SNVs, MNVs, indels and SVs/MEIs, genomic positions and mutation annotations using the PCAWG dataset. This model contained one attention head and two encoder layers, embedding dimension 512, resulting in 28,458,520 trainable parameters." That is the sparse data analysis model. The remainder of the PCAWG experiments after the typing evaluation also used an ensemble trained on SNVs, MNVs, indels, and SVs and MEIs, with genomic positions, in PCAWG data. Results, Evaluation of histological tumour typing performance. Note the small wording difference between the two places: the Fig. 2a best combination is stated as SNVs, MNVs, indels, and genomic position, while the ensemble used for later experiments is stated with SVs and MEIs and positions. Record both statements as published, and do not merge them into one recipe.

Comparator models in the same paper, for context: a DNN and random forest following Jiao et al., cited as reference 20 in MuAt, and a random forest on SBS, DBS, and ID signature features extracted in PCAWG. Methods, Comparing MuAt with other models. The signature random forest reached 81.4 percent with all three signature types combined, and 68.3 percent for SBS alone, 42.1 percent for DBS alone, and 66.0 percent for ID alone. Results, Evaluation of histological tumour typing performance, and Additional file 1, Table S3a as cited there. Those signature numbers are fitted signature feature numbers, which makes the contrast with Section C.3 clear: Sanjaya et al. 2023 name fitted signature features as signatures and counted channels as counts, while Lee et al. 2019 use the word signatures for counted channels.

### D.3 Cohorts and metrics, as published

Cross validated typing, Fig. 2a and Results, Evaluation of histological tumour typing performance:

- PCAWG whole genomes, 2,587 tumours, 24 types: top 1 accuracy 88.8 percent. Top 3 accuracy 96.1 percent, stated in the results summary in Background. Top 5 accuracy 97.4 percent for the best Fig. 2a combination. Abstract rounds top 1 to 89 percent and top 5 to 97 percent.
- TCGA exomes, 7,352 tumours, 20 types: top 1 accuracy 64.1 percent, top 5 accuracy 90.6 percent. Results, same section, and Fig. 2a. Abstract rounds top 1 to 64 percent and top 5 to 90 percent.
- Comparators in Fig. 2b: the Jiao et al. style DNN reached 85.5 percent in PCAWG and 62.8 percent in TCGA. Random forest on mutations reached 75.2 percent in PCAWG and 54.7 percent in TCGA. Results, same section.
- MSI handling differs from the DNN original report. MuAt kept MSI tumours in the data, while the DNN paper had removed them before training, which the MuAt authors give as a possible reason that their own DNN rerun reached 85.5 percent rather than the 91 percent reported by Jiao et al. Results, same section. Any cross paper DNN comparison must carry that note.

Independent whole genome evaluation, same Results section and Additional file 1, Table S3 as cited there:

- ICGC tumours not in PCAWG, matched types: MuAt fold models 85.1 percent mean accuracy, ensembles 90.6 percent. DNN fold models 82.4 percent, ensembles 86.7 percent.
- Genomics England, 9,796 tumours of matched types: MuAt fold models 75.6 percent, ensembles 81.8 percent. DNN 73.0 percent and 78.4 percent. Random forest 69.7 percent and 72.2 percent.
- Colorectal cohort, 256 tumours, variants called with MuTect v1.1.4: MuAt 76.7 percent, DNN 75.4 percent for fold models, and 80.5 percent and 81.6 percent for ensembles.
- Unfiltered Genomics England calls: performance fell for all models, and MuAt accuracy rose from 47.6 percent on unfiltered data to 70.6 percent after removal of a named artefact class, compared with 75.9 percent on high quality data. Results, same section, and Additional file 1, Table S3c as cited there. This is direct published evidence that call quality and filtering change the same model score by a large amount on the same cohort.

Burden effects, Fig. 3: tumours with under 1,109 mutations were predicted at 81 percent, tumours with over 29,626 mutations at 85.5 percent, and tumours in between at 90.4 percent. Results, same section, and Fig. 3a. In downsampled sparse data, accuracy reached 71.1 percent at about 500 mutations per sample, with top 5 accuracy 95.6 percent at 500 mutations. Results, same section, and Fig. 3d.

Subtype findings are representation findings, not typing metrics: learned tumour level features separated groups that were never given as labels, including SPOP mutated prostate cancers, SHH activated medulloblastomas, microsatellite unstable and POLE proofreading deficient tumours, CCND1 amplified acral melanomas, and MUTYH germline associated pancreatic neuroendocrine tumours. Abstract, Results, MuAt distinguishes molecular tumour subtypes, and Fig. 4. They support a claim about what the learned features contain. They do not add a typing accuracy that can be compared with a tabular benchmark.

## E. Comparability warnings: why the published numbers must not be compared directly with balanced accuracy on the manuscript 20 type TCGA cohort

Balanced accuracy is the mean of per class recall. It weights a small cancer type the same as a large one. None of the three headline numbers above is a balanced accuracy, and none was measured on the manuscript cohort, label set, input territory, or feature rules. Direct comparison would compare unlike quantities. The specific mismatches:

1. Metric mismatch comes first. Ozcan Simsek 2019 reports micro averaged accuracy on a test set. Methods, Evaluation strategy, and Table 6. Lee et al. 2019 reports average accuracy from nested cross validation, with Fig. 4 and Table 1 and Table 2 as described in Results. Sanjaya et al. 2023 reports top 1, top 3, and top 5 accuracy. Fig. 2. Overall accuracy rewards doing well on frequent types. Balanced accuracy does not. A model can have high overall accuracy and poor balanced accuracy on the same predictions if it fails on small types.
2. The papers themselves show small types failing under high headline scores. Ozcan Simsek 2019, Table 7: per class f-score ranges from 39.80 percent for Prostate and 51.40 percent for Thyroid to 95.92 percent for Breast, under the 76.44 percent headline in Table 6. Lee et al. 2019, Discussion: CHOL had only 35 samples and 31.43 percent average accuracy, under the 84.09 percent headline for 31 types. A balanced accuracy on 20 types would surface exactly these failures. The published headlines hide them by construction.
3. Label sets differ, so the task differs. Ozcan Simsek 2019 uses 10 broad grouped labels such as Lung, Brain, and Skin. Table 1. Lee et al. 2019 uses 31 TCGA types. Methods, Feature Construction. Sanjaya et al. 2023 uses 24 PCAWG histological types for whole genomes and 20 TCGA types for exomes, and the 20 TCGA types there are the types with more than 100 tumours in the MC3 set, which is a selection rule, not a promise that the type list or patient list matches the manuscript 20 type cohort. Methods, Data. Fewer or broader classes are an easier task. The papers show this inside their own results: Lee et al. 2019 rises from 84.09 percent on 31 types to up to 94 percent on the 6 most frequent types. Discussion, and Supplementary Fig. S3 as cited there.
4. Input territory differs, and territory moves scores more than representation choice often does. Ozcan Simsek 2019 uses exonic plus intronic mutations from whole VCF files, and reports that exonic only data falls to 54.56 percent accuracy while intronic only data gives 74.39 percent, against 76.44 percent for all mutations. Table 8. Sanjaya et al. 2023, with the same method family, falls from 88.8 percent on whole genomes to 64.1 percent on exomes. Fig. 2a. A coding mutation only TCGA cohort is a third territory. None of these numbers predicts a score in the other territories.
5. Extra inputs differ. Full CPEM uses copy number log2 ratios, rates, spectra, and context channels on top of gene counts. Section C. MuAt uses genomic position and per mutation annotation, and in whole genome mode uses SVs and MEIs that an exome MAF does not contain. Section D. Ozcan Simsek 2019 headline uses a class dependent transform that cannot be applied to an unlabeled patient as written. Section B. Comparing any of these headlines with a mutation only, inference safe, balanced accuracy benchmark credits or blames the representation for differences that belong to inputs, territory, and evaluation rules.
6. Validation designs differ. Ozcan Simsek 2019: one 80 to 20 split family with 10 fold tuning and test reporting as described in Methods, Evaluation strategy. Lee et al. 2019: nested 10 fold cross validation with supervised feature selection inside the inner loop. Fig. 2. Sanjaya et al. 2023: 10 fold cross validation, per fold hyperparameter selection, and ten model ensembles for headline reporting. Methods, MuAt hyperparameter search, model training and validation. Ensemble and searched numbers are not single model numbers. A benchmark that reports a single learner, or a fixed tuning budget, per representation is measuring a different protocol.
7. Cohort composition and call quality differ. Mutation burden, type mix, caller, filtering, and reference build all move scores. Sanjaya et al. 2023 show one model moving from 47.6 percent to 75.9 percent on Genomics England tumours depending only on call filtering. Results, Evaluation of histological tumour typing performance. Ozcan Simsek 2019 grouped types have very unequal sizes, from 378 Liver to 1,232 Lung samples. Table 1. Prevalence differences alone change overall accuracy without any change in per class skill, which is the exact distortion balanced accuracy was chosen to remove.

Correct use of these papers in the manuscript: cite them for representation definitions, for the CPEM count block versus full model distinction, for the MuAt token and attention design and its searched training protocol, and for the finding that territory and filtering dominate typing scores. Do not place 76.44 percent, 84.09 percent, 88.8 percent, or 64.1 percent in a results table next to the manuscript balanced accuracy values, and do not describe any of them as a performance bar that the manuscript representations beat or missed. The only fair performance comparisons are reruns on the same patients, same labels, same splits, same eligibility rules, and same metric, with every learned transform fitted inside training data.
